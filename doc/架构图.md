# modelclaw 架构图（架构多视图）

> 复盘用学习地图：六张图从宏观到细节覆盖整个项目。
> 全部 Mermaid 编写（Diagram as Code），GitHub / VS Code 原生渲染。
> 每张图附「读图指南」：怎么看 + 对应哪些代码文件。

## 图 1 · 系统上下文图（这个项目活在什么世界里）

```mermaid
flowchart TB
    user([用户])
    subgraph local[本机]
        cli[modelclaw CLI<br/>typer + Rich · 16 个命令]
        api[FastAPI 服务<br/>server.py · modelclaw serve]
        sqlite1[(sessions.db<br/>SQLite 会话库)]
        sqlite2[(rag.db<br/>sqlite-vec 向量库)]
        files[(output/<br/>结果文件 + 日志)]
    end
    pg[(PostgreSQL 18<br/>modelclaw 库<br/>会话 + pgvector + LangGraph 检查点)]
    ms[/ModelScope<br/>LLM 推理 API/]
    ds[/DashScope<br/>嵌入 API/]
    hf[/HF Mirror<br/>本地 reranker 模型/]

    user --> cli
    user --> api
    cli --> ms
    cli --> ds
    api --> ms
    api --> ds
    cli --> pg
    api --> pg
    cli --> sqlite1
    cli --> sqlite2
    cli --> files
    api --> files
    cli --> hf
```

**读图指南**：系统有两个入口（CLI / HTTP），三个云端依赖（LLM、嵌入、模型镜像），存储四处分布（PG、两个本地 SQLite 文件、output/ 目录）。PG 一个库同时承载三类数据：会话、向量、LangGraph 检查点。
**对应文件**：`modelclaw.py`（CLI）、`server.py`（HTTP）、`config.json`（所有连接参数）。

**读图指南**：三层结构——编排层不碰业务，能力层不碰存储细节，支撑层不知道谁调用它。注意箭头方向：`modelclaw.py` 指向一切，但没有任何模块指回它。配置从右侧「驱动」所有层（虚线）。
**对应文件**：图里的每个节点就是同名 .py 文件。

## 图 3 · 数据库 ERD（表关系全图，已与真实 schema 核对）

```mermaid
erDiagram
    SESSIONS ||--o{ MESSAGES : "session_id"
    SESSIONS {
        text session_id PK "会话ID（chat_YYYYMMDD_HHMMSS）"
        text title "首条用户消息截断30字"
        text summary "滚动摘要（context_engine 写入）"
        text created_at "创建时间"
        text updated_at "最后活跃"
    }
    MESSAGES {
        bigint id PK "自增"
        text session_id FK "所属会话"
        text role "user / assistant"
        text content "消息原文"
        text created_at "时间"
    }
    RAG_CHUNKS {
        bigint id PK "自增"
        text source "来源文件路径"
        int chunk_index "块序号"
        text content "块文本"
        vector embedding "vector(1024) pgvector 扩展"
    }
    RAG_META {
        text key PK "如 embedding_dim"
        text value "维度记账，防错配"
    }
```

上图是 **PostgreSQL（modelclaw 库）**。本地 SQLite 是同构设计：

| SQLite 文件 | 表 | 与 PG 的差异 |
|---|---|---|
| `output/sessions.db` | `sessions` + `messages` | 结构完全一致（自增列类型不同：INTEGER vs BIGINT） |
| `output/rag.db` | `chunks` + `vec_chunks`（虚表）+ `rag_meta` | sqlite-vec 双表设计：向量在虚表，靠 rowid 关联 chunks.id |

LangGraph 引擎启用后，PG 里还会出现官方 checkpointer 的 4 张表：`checkpoints` / `checkpoint_blobs` / `checkpoint_writes` / `checkpoint_migrations`（框架自管，应用代码不直接读写）。

**读图指南**：一对多关系只有一条——会话拥有消息。RAG 侧没有外键：向量是可从源文档重建的派生数据。`rag_meta` 是 M3.5 修的「维度硬编码」缺口的产物。
**对应文件**：`session_store.py` / `postgres_store.py` / `rag_store.py` / `pgvector_store.py`（各文件顶部的 SCHEMA 常量）。

## 图 4 · 核心序列图（三条主链路）

### 4a. chat 一轮（会话记忆 + 上下文工程）

```mermaid
sequenceDiagram
    participant U as 用户
    participant CLI as modelclaw.py
    participant CE as context_engine
    participant DB as SessionStore
    participant LLM as ModelScope

    U->>CLI: chat "我叫卡尔"
    CLI->>DB: add_message(user)（先落库）
    CLI->>CE: build_context()
    CE->>DB: get_messages + get_summary
    alt 历史超阈值
        CE->>LLM: complete() 压缩旧对话（非流式）
        CE->>DB: set_summary + 删已摘要消息
    end
    CE->>CE: trim_messages 裁剪 + 最新消息兜底
    CE-->>CLI: [system] + [摘要] + 裁剪后历史
    CLI->>LLM: ask() 流式
    LLM-->>U: Thinking / Final Answer 逐字渲染
    CLI->>DB: add_message(assistant)
```

### 4b. agent 一轮（工具调用循环）

```mermaid
sequenceDiagram
    participant U as 用户
    participant AG as agent.py run_agent
    participant LLM as ModelScope
    participant T as tools.py

    U->>AG: "计算88×11再告诉我时间"
    AG->>LLM: ask_with_tools(消息 + 工具说明书)
    LLM-->>AG: tool_calls: calculator("88*11")
    AG->>T: run_tool("calculator", ...)
    T-->>AG: "968"
    AG->>LLM: 回灌 assistant(tool_calls) + tool(968)
    LLM-->>AG: tool_calls: get_current_time()
    AG->>T: run_tool(...)
    T-->>AG: "2026-10-09 ..."
    AG->>LLM: 回灌结果
    LLM-->>U: 最终答案（无 tool_calls 则收尾）
    Note over AG,LLM: 超过 max_iterations 则报错兜底
```

### 4c. ask 一轮（RAG 三级检索管线）

```mermaid
sequenceDiagram
    participant U as 用户
    participant RAG as rag.py
    participant EMB as DashScope 嵌入API
    participant V as 向量库
    participant BM as BM25(内存)
    participant RR as bge-reranker
    participant LLM as ModelScope

    U->>RAG: ask "retry组有哪些字段"
    RAG->>EMB: 问题向量化
    par 双通道并联（数据独立）
        RAG->>V: KNN top-12（语义通道）
    and
        RAG->>BM: 关键词检索 top-12（字面通道）
    end
    RAG->>RAG: RRF 融合
    RAG->>RR: 候选 12 块重排
    RR-->>RAG: top-6 + 得分
    alt top1 得分 < 0.1
        RAG-->>U: 直接拒答（零 LLM 成本）
    else
        RAG->>LLM: 系统提示词(块) + 问题
        LLM-->>U: 流式回答 + 引用来源表
    end
```

**读图指南**：三条链路共享同一个 LLM 但用法不同——chat 走流式、agent 走工具协议、ask 走检索增强。注意 4c 的「并联」是两个检索通道数据独立（M3 学习里掰扯过的那点）。
**对应文件**：`modelclaw.py` / `agent.py` / `rag.py` / `context_engine.py`。

## 图 5 · 可插拔结构图（四个配置开关 × 双实现）

```mermaid
flowchart LR
    subgraph switches["config.json 的四个开关"]
        e1["llm.engine"]
        e2["agent.engine"]
        e3["memory.backend"]
        e4["rag.backend"]
    end

    e1 -->|native| n1[api_client.py<br/>原生 OpenAI SDK]
    e1 -->|langchain| n2[llm_langchain.py<br/>ChatOpenAI + LCEL + 补丁]
    e2 -->|native| n3[agent.py<br/>手写循环]
    e2 -->|langgraph| n4[agent_langgraph.py<br/>create_react_agent]
    e3 -->|sqlite| n5[SqliteSessionStore]
    e3 -->|postgres| n6[PostgresSessionStore]
    e4 -->|sqlite-vec| n7[SqliteVecStore]
    e4 -->|pgvector| n8[PgVectorStore]

    n5 -.同一契约.-> n6
    n7 -.同一契约.-> n8
```

**读图指南**：四个开关各自独立、可任意组合。每个开关背后的两个实现都满足同一份接口契约（SessionStore / RagStore 的 ABC），`tests/` 里的契约测试就是证明。这是 Repository 模式贯穿 M1.5 → M3.5 → M4 的三次实践。
**对应文件**：`session_store.py` / `rag_store.py` 底部的工厂函数；`api_client.ask()` 与 `modelclaw.py agent` 命令里的引擎分发。

## 图 6 · 演进路线图（这个项目怎么长出来的）

```mermaid
flowchart LR
    M0["M0 裸 API 调用<br/>main.py + 重试 + 落盘"]
    M1["M1 会话记忆<br/>session_store / context_engine<br/>SQLite→PG 双后端"]
    M2["M2 Agent<br/>agent.py / tools.py<br/>手写 tool_calls 循环"]
    M3["M3 RAG<br/>rag / embeddings / rag_store<br/>混合检索 + 重排"]
    M4["M4 质量与框架<br/>llm_langchain / agent_langgraph<br/>evaluator / server / tests"]

    M0 --> M1 --> M2 --> M3 --> M4
```

**读图指南**：每个里程碑新增一组模块，但从不推翻前一层——记忆给 Agent 用、检索给评估用、契约测试保护重构。「从零重建」的秘诀就在这条路径里：按 M0→M4 的顺序，每个阶段只加一层。
**对应文件**：`doc/M1学习计划.md` ~ `doc/M4学习计划.md`（每阶段的学习笔记与验收清单）。
