## M4 总目标

把 modelclaw 从「功能完整的 CLI」升级为「质量可验收、框架全覆盖、可服务化交付」的产品级项目。完成后简历叙事线闭环：

M1 会话记忆工程化 → M2 Agent 工具调用 → M3 RAG 知识库 → M4 质量保障与框架实战

框架覆盖目标：LangChain（LCEL / ChatOpenAI / with_structured_output）+ LangGraph（create_react_agent / checkpointer）全部有主链路级实战，且原生手写实现全部保留为可切换引擎。

## M4a0 · LangChain 主链路重构（框架上山）

**目标**：用 LangChain（ChatOpenAI + LCEL）重构 chat 主链路的模型调用层，保留全部现有特性，双引擎可切换。

**前置验证尖刺（必须先做，结果决定本阶段形态）**：
- ChatOpenAI 流式调 ModelScope 的 DeepSeek-V4.1，验证 reasoning_content 是否透传到 AIMessageChunk.additional_kwargs
- 若透传正常 → 全量重构；若不透传 → **停下通知用户**，展示证据，共同决定（绕开/放弃该特性/换模型），不擅自砍特性

**特性保留清单（验收对照表）**：
| 特性 | LangChain 对应物 | 验收方式 |
|---|---|---|
| 配置驱动重试 | with_retry() / max_retries（底层即 tenacity） | 断网/限流时重试行为与原生版一致 |
| 流式输出 | chain.stream() | Thinking / Final Answer 渲染不变 |
| 思维链分离 | additional_kwargs 中的 reasoning_content | 验证尖刺决定 |
| 会话记忆/上下文工程 | 不变（build_context 产出照常喂入） | resume 记忆回归 |
| 结果落盘 | 不变 | /save、单发落盘回归 |

**双引擎**：config.json 加 llm.engine: native | langchain，默认 langchain；原生实现永久保留作为参照实现。

**验收**：chat 单发 + REPL 在两种引擎下行为一致；engine 一行切换。

## M4a · 评估体系（用掉 评估Evaluation.py，LangChain/LCEL 主场）

**目标**：新增 `modelclaw eval` 命令，实现 LLM 应用的自动化质量评估。

**内容**：
1. 测试集自动生成：从知识库文档自动生成问答对（出题链：PromptTemplate | ChatOpenAI | 解析器，对应笔记的 QAGenerateChain 现代版）
2. 批量预测：.batch() 并行跑 RAG 管线（对应笔记的 chain.batch）
3. LLM-as-a-Judge 判分：判分链 + with_structured_output(Pydantic) 输出 {grade, reason}
4. Rich 报告：准确率、失败用例明细（问题/标准答案/预测/判分理由）
5. 评估对象首选 RAG 的 ask（顺便把 M3 的阈值校准从手工升级为数据驱动）；支持 --output 存评估报告文件

**验收**：modelclaw eval 完整跑通一轮：生成 ≥5 个问答对 → 批量预测 → 判分 → 打印准确率报告；报告文件落盘。

## M4b · pytest 测试套件（补上工程空白）

**目标**：建立 tests/ 目录，核心逻辑有自动化测试保护。

**内容**：
- 双后端契约测试：同一套用例跑 SessionStore（sqlite/postgres）与 RagStore（sqlite-vec/pgvector）——接口契约的可执行证明
- context_engine：count_tokens / 摘要触发 / 裁剪 / 安全网（LLM 调用 mock 掉）
- tools：沙箱越界拒绝、eval 注入拦截、未知工具、坏 JSON
- 存储/落盘：save_result 三种格式
- eval 接进回归：准确率显著下降时报测试失败（阈值可配）
- 命令：python -m pytest 一键全绿

**验收**：pytest 全绿；契约测试双后端都跑；不依赖真实 LLM 的用例离线可跑，依赖的用例打标记可跳过。

## M4c · LangGraph 重构 Agent（兑现 M2 承诺，回收 PG 伏笔）

**目标**：用 LangGraph create_react_agent + PostgresSaver 重构 Agent，与手写引擎共存可切换。

**内容**：
1. langgraph + langgraph-checkpoint-postgres 接入；checkpointer 用本机 PG（M1.5 伏笔第二次回收）
2. tools.py 工具适配为 @tool 格式（双注册：原生 dict 给手写引擎，@tool 给 LangGraph）
3. config.json 加 agent.engine: native | langgraph
4. 对照文档：手写循环 vs LangGraph 节点/边/state 的逐层映射（写进代码注释或文档）

**验收**：同一任务（多工具组合）在两种引擎下都能完成；LangGraph 引擎的会话经 checkpointer 持久化、可 --resume；双引擎切换回归。

**风险预案**：langgraph-checkpoint-postgres 的 Windows 兼容性、与现有 sessions 表的关系（并存还是迁移）若出现意外 → 停下通知用户。

## M4d · FastAPI 服务化

**目标**：把 chat / ask / agent 包成 HTTP API，CLI 成为 API 的客户端之一。

**内容**：
1. FastAPI 应用：POST /chat、POST /ask、POST /agent（SSE 流式响应）
2. 配置驱动端口/主机；启动命令 modelclaw serve
3. PG 后端在服务化场景的价值兑现（多并发共享会话）
4. README 补 API 调用示例（curl）

**验收**：modelclaw serve 启动后，curl 三个端点均返回正确结果；流式端点 SSE 逐块到达；CLI 全功能不受影响。

## 执行顺序与升级协议

M4a0 → M4a → M4b → M4c → M4d

**升级协议（触发即停下通知用户）**：
- 需要安装大型软件/服务（Docker、新数据库等）
- 需要新的 API key / 付费资源 / 配额不足
- 框架兼容性问题导致特性可能丢失（如 reasoning_content 不透传）
- 任何需要删改既有功能才能继续的情况
- 预计阻塞超过 30 分钟的环境问题

**完成定义**：本文件五个阶段的验收项全部实测通过 → 才撰写 doc/M4学习计划.md → 更新 README 演进路线（M4 勾上）→ 用户提交推送。
